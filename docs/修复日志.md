## 已落地修复条目（有证据）

### 1. 单机 / 多音箱 MiPlay 与 Legacy / Safety 认证路径（代码存在）

- **事实**：核心会话支持 `AuthMode::{Legacy, Safety, Auto}`（`core/src/session.rs`）；JNI `setAuthMode`（`core/src/ffi.rs`）；UI 认证选项经 `AuthModeResolve`（有 `AuthModeResolveTest`）。
- **证据提交**：功能贯穿基线与后续连接诊断提交（如 `57d5d0e`、`feb37b5`）；单测类 `AuthModeResolveTest` 计入 0.9.3 验收 JVM 套件。
- **测试范围**：JVM 认证解析单测；**真机全矩阵「Safety/Legacy × 单/多箱」通过情况：待核实**（仓库 docs 对 LX06 等明确「不宣称已修好」：`docs/LX06_V8_POSTMORTEM.md`）。
- **用户 0.9.3 华为可投送**：仅证明该机该包可投送路径可用，**不**自动覆盖所有认证组合与双箱听感。

### 2. CastService `localMute` 构造期崩溃（0.9.2）

- **现象（文档记录）**：小米 17 Pro、acceptance 0.9.1（versionCode 10），MediaProjection 授权后 `CastService` 启动 NPE（`getApplicationContext` 于未 attach 的 Service）。
- **修法**：`lateinit localMute`，`onCreate` 后用已附加 Context 构建；`AndroidStreamMusicVolume` 注入 `AudioManager`。
- **证据**：提交 `870e4a6`；文档 `docs/CASTSERVICE_MUTE_INIT_CRASH.md`；回归 `CastServiceMuteInitTest`。
- **版本**：versionCode **11** / `0.9.2-cast-panel`（acceptance 后缀由 flavor）。
- **测试范围**：JVM 构造路径回归；真机是否复测 0.9.2：**待核实**（后续用户确认的是 **0.9.3**）。

### 3. minSdk 29 真实兼容（0.9.3，非仅改数字）

- **证据**：`60f54ee` 引入 `CaptureSelectionLayers`；`MainActivity` / `AppPickerActivity` / `CastService` 文案与日志调用；契约测试 `Api29CompatContractTest.captureSelectionLayers_areDistinct`。
- **测试范围**：JVM 文案契约；真机「选错音源导致静音」场景：**产品说明已落地，个案是否复现待用户侧**。

### 5. 静音探针不误报「已验证成功」

- **证据**：`LocalOutputMute.kt`（`60f54ee`）；`LocalOutputMuteUnverifiedTest`；`docs/LOCAL_MUTE.md`。
- **测试范围**：JVM；真机探针行为：**未在本日志宣称通过**。
