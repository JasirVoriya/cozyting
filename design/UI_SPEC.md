# 妙投（MiaoCast）跨端 UI 设计规范（Android + 未来 iOS）

本目录是 **第 3 层（UI 表现层）** 的唯一视觉事实来源：Android（Kotlin 原生 View）与后续 iOS（SwiftUI）分别按原生方式实现界面，但严格共用本目录的 `tokens.json`、`icons/*.svg` 与页面信息架构。

- **品牌名与协议名解耦约定**：C 端产品名称统一为 **妙投**（英文 locale 为 **MiaoCast**）；底层协议与引擎标识统一保留 **MiPlay**（如设备行协议徽标 `MiPlay`、设置项中的「未声明 MiPlay 能力的节点」、L1 Rust 核心 `miplay-core`）。

## 1. 视觉风格（第一版样式 B · 克制低饱和 + 高对比选中卡）

- **主题支持**：三态切换 `跟随系统（默认）` / `浅色` / `深色`，即时生效且同步系统状态栏与导航栏图标反色（Edge-to-Edge）。
- **深色模式（Dark）**：深炭蓝微透面板 `#151A23` + 轻描边 + 未选中微透深灰行；**已选中音箱行采用亮白浅卡 `#EAF0F7` 反显**（深墨字 `#12161E` + 主题蓝 `#2563EB` 滑块与勾选），一眼锁定当前投送设备。
- **浅色模式（Light）**：清爽冷浅灰底 `#F4F6FA` + 纯白面板/未选中卡；**已选中音箱行采用淡蓝底 `#EBF3FF` + `1.5dp` 主题蓝描边 `#2563EB`**（深墨字 `#0F172A` + 主题蓝滑块与勾选）。
- **专辑封面氛围底**：低饱和克制透色——API 31+ 使用 `RenderEffect` 模糊 + 明暗自适应遮罩；API 29–30 使用轻量缩略图软模糊；iOS 使用原生 `.ultraThinMaterial`；无封面时使用柔和双色渐变（严禁生硬像素色块）。

## 2. 四段式主界面结构（双端对齐）

1. **顶栏（Top Bar）**
   - 左侧：品牌标题（中文 `妙投` / 英文 `MiaoCast`，双端统一）+ 运行状态胶囊（状态圆点 + `本机出声` / `投送中 · N 台` / `连接中`）。
   - 右侧：紧挨排列「**延迟模式快捷胶囊**」与「**设置**」圆形图标按钮（标准 6 齿齿轮图标；当存在未忽略的新版本时在设置按钮右上角叠放 `8dp/pt` 主题蓝圆点角标）；深色/浅色/跟随系统三态切换统一收敛在独立设置页「外观与发现」卡片中，设备刷新按钮下沉至「输出设备」标题栏。
   - **非阻塞版本更新轻提示条（顶栏下方、主面板上方）**：仅在非投送态检测到未忽略新版本且本次会话未手动关闭时展示单行紧凑提示条（`update.svg` + `发现新版本 vX.Y.Z` + `查看` 胶囊 + `×` 关闭）；投送中自动隐藏，绝不在冷启动强行弹出阻塞型弹窗打断听歌与选箱。
   - **延迟模式快捷胶囊与极简下拉菜单（Android & iOS 双端对齐）**：
     - 单一事实来源：仅由持久化 `delayMs`（`0` = 自动，`> 0` = 具体毫秒）自动推导，绝不维护第二份模式枚举；
     - 4 个内置档位各配独立 `24×24` 几何线性图标：`标准`（`latency_standard.svg`，自动 5GHz 800ms / 2.4GHz 1000ms，14 AU，中性色）、`均衡`（`latency_balanced.svg`，400ms，8 AU，主题蓝）、`低延迟`（`latency_low.svg`，250ms，5 AU，主题蓝）、`极速`（`latency_ultra.svg`，150ms，3 AU，暖琥珀）；若用户在设置页手动填写了非预设值，胶囊自动显示 `latency_custom.svg` + `${delayMs}ms`（`<250ms` 琥珀 / `≥250ms` 蓝），下拉框 4 个预设均不勾选并在底部动态追加一行已勾选的 `自定义 · Nms`；
     - 下拉菜单保持极致精简（宽约 `196–200dp/pt`，单行仅展示「图标 + 档位名 + 右侧 ms + 勾选」，零长文说明），点击任意预设立即调用 L1 `miplay_engine_set_playback_delay` / `NativeBridge.setPlaybackDelay` 热重锚 `TIME_OFFSET` 即时生效（免断连重连），且冷启动按 L1 `startup_runway_aus_for_delay_ms` 自动缩放预热帧数；
     - 下拉框底部经细分割线提供按需入口 `ⓘ 档位说明 ›`，点击后弹出详情弹窗展示 4 档完整参数、适用场景与「去设置自定义 ms」跳转（Android 使用 `PopupWindow` + Style B `Dialog`；iOS SwiftUI 使用 `Menu` + `.sheet` 对应实现）。
2. **正在播放区（Now Playing）**
   - **已获得活跃媒体会话**（双端统一左大封面 + 右文控结构）：
     - **左侧封面**：放大至 **`96dp/pt × 96dp/pt`**（`16dp/pt` 圆角，Android 通过 `Canvas.clipPath` + `clipToOutline` 双重稳定裁剪），与右侧文控区高度齐平；右下角叠放 **`26dp/pt` 圆形音源 App Logo 角标**（带细描边与微投影确保亮/暗封面均清晰可辨）。
     - **右侧列**：高度 `96dp/pt`，左距封面 `16dp/pt`（与主卡片左右 `16dp/pt` 内边距三处等距）；整体在 `96dp/pt` 高度内垂直居中，且歌名（`17.5sp/pt` Bold，单行省略）、歌手名（`12.5sp/pt` 次级色）与下方播控按钮组（`上一首 38dp/pt 柔和圆底` · `26dp/pt 间距` · `播放/暂停 42dp/pt 高对比主圆钮` · `26dp/pt 间距` · `下一首 38dp/pt 柔和圆底`）统一沿同一垂直中轴线居中对齐。
     - **点击封面跳转音源 App**：
       - **Android**：点击封面（带圆角水波纹反馈）优先通过 `nowPlaying.sourcePackage`（回退已选音源 `selectedPackage`）调用 `getLaunchIntentForPackage()` 拉起对应音乐 App。
       - **iOS（SwiftUI）**：同布局与右下角角标槽位；受 iOS 沙箱限制无法遍历任意第三方 App 图标或按 Bundle ID 强拉起，角标展示已知音源/系统音频图标，点击封面时对支持 URL Scheme 的音乐 App 跳转（如 Apple Music `music://`），未知音源则静默降级不报错。
     - **进度条与音量条（双端统一细轨道规范）**：播放进度条采用全宽 **`4dp/pt` 居中细胶囊轨道** + `14dp/pt` 圆形滑块，当前时间（左）与总时长（右）紧贴轨道下方两侧（播放中平滑走字，拖拽实时更新）；Android `SeekBar` 的 `LayerDrawable` 必须显式锁定图层高度为 `4dp` 并垂直居中，防止系统拉伸成粗条；下方紧接带实时百分比的总音量细轨道滑块。
   - **未获得媒体会话/无通知使用权**：折叠为单行可点击引导条（Android 点击直达通知使用权设置；iOS 展示广播捕获/音频会话提示）+ 总音量条，不占位浪费。
3. **音源槽位（Platform Audio Source Slot）**
   - **Android**：
     - 当前选定 App 卡片（图标 + 名称 + 自动识别态显示 `自动识别` 胶囊 + `管理` 入口）+ 横向快捷切换胶囊（严格按用户自定义「常用音源」排序展示，亦支持长按胶囊左右拖动排序并实时持久化；若当前临时选定非常用 App 则置前提示）；未选 App 直接点音箱时拉起 `AppPickerActivity`。
     - **常用音源管理页（`AppPickerActivity`）**：支持用户自由增删与**长按拖动排序**「常用音源」名单（首次默认带入本机已安装的内置音乐/播客 App；卡片 ≥ 2 张且非搜索态时右侧显示 `drag_handle.svg` 拖拽把手与「长按拖动排序」提示，拖动浮起并平滑让位换位、松手持久化且不误触点击或开关）；每个常用音源卡片下方提供独立的 **`自动识别` 开关**与 **`移出常用`** 按钮，下方其他应用行提供 **`+ 常用`** 胶囊按钮。
     - **自动识别与投送中热切换策略**：开启全局开关后，监听全部活跃 `MediaSession` 的播放状态上升沿，严格从「常用音源名单」中开启独立 `自动识别` 开关的 App 内匹配最新起播音源——待机时自动预选，投送中切换至其他常用音乐 App 播放时（即便旧软件未关闭）由前台服务 `CastService` 在不断开音箱的前提下经 `CaptureTargetResolver` 单 UID + 签名 fail-closed 校验后热重建 `AudioRecord` 切换捕获目标；若系统限制复用当前 `MediaProjection` 则 fail-closed 保持原音源或干净停止并提示重授，绝不退化为全系统捕获；手动切源后防止被后台仍在播放的旧会话立刻拉回。
   - **iOS（未来）**：同一视觉卡槽展示 `ReplayKit` 系统广播捕获入口（`RPSystemBroadcastPickerView`）或 App 内音源状态；受 iOS 沙箱限制无法读取第三方 App `MediaSession` 包名，也不按单 App UID 选源，因此常用音源增删、长按拖动排序与自动识别开关仅作用于 Android 端。
4. **输出设备区（Output Devices）**
   - 分节标题栏：左侧 `输出设备`，右侧展示已发现设备数 + **`28dp/pt` 圆形刷新扫描按钮**（仅刷新局域网输出设备，扫描中旋转动画），避免放在顶栏造成全局刷新的语义误解。
   - 首行：`本机播放`（与外部接收端互斥，标题字号与外部设备行统一为 `13sp/pt Bold`）。
   - 外部音箱/电视行：统一矢量图标（音箱/电视）+ **同行轻分隔标题「设备名 + 可选房间名」**（单行末尾省略，不拼接型号后缀；设备名采用 `13sp/pt Bold` 主色，获取到非空房间名时紧随 ` · <房间名>` 采用 `11.5sp/pt Regular` 次级色，无房间名或获取不到时彻底隐藏、不留分隔符；Android 通过 `SpannableStringBuilder` 实现，iOS SwiftUI 通过 `Text(name).font(.system(size: 13, weight: .bold)) + Text(" · \(room)").font(.system(size: 11.5)).foregroundStyle(subColor)` 等价实现；双端统一消费第 1 层 Rust `miplay_discover_json_ex`，单次只读 TCP 8899 `GET_DEVICE_INFO` TLV 帧内同步提取 `miName` 与 `roomName`，名称优先级为「`miName` → 本地缓存 `miName` → mDNS 老名字 → IP」，音箱与电视一视同仁、投送中跳过查名；冷启动自动扫描沿用已含 `room_info_queried=true` 的本地缓存，首次发现/缺房间字段的旧版缓存或手动刷新时触发查名）+ 副标题（IP + 实时状态：`投送中` / `连接中…` / `重连中…` / 不可投送原因）+ 右侧延迟胶囊（直接消费第 1 层 Rust 下沉的 `ui_state` 与 `display_latency_ms`）+ 协议徽标 + 矢量勾选圆。
   - 选中后行内展开带实时百分比的独立音量滑块；拖动音量时仅原位更新，禁止重建设备列表。

## 3. 独立设置页（4 张卡片分组）

1. **外观与发现**：三段式主题选择 `[跟随系统 | 浅色 | 深色]`、显示全部发现设备开关、重新发现设备入口。
2. **投送与系统权限**：
   - **采集引擎（Android 专属；iOS 受沙箱模型限制由 `ReplayKit` 固定承载，不展示此分段）**：两段式切换 `[标准投屏模式 | 无感模式（无线调试）]` + 系统版本能力分层说明（未手动选择时按系统版本自动决定默认项：**Android 13+ 默认无感模式**；Android 10–12 默认标准投屏模式以守住单 App Fail-Closed 红线）；选择无感模式且 Android 11+ 时展示内置无线调试配对状态行（`已配对` / `未配对`，无需 Shizuku 等外部 App）、捕获范围分段 `[单 App 隔离 | 全局媒体（显式）]`（Android 11–12 选单 App 时 Fail-Closed 提示）、`打开 4 步配对引导` / `查看向导 / 重新配对`、`测试连接` 与 `清除本机配对证书`。
   - **4 步交互式配置向导页（`WirelessDebugGuideActivity`，Android 专属）**：严格沿用 Style B 明暗主题与顶部进度胶囊，实时自动检测并打勾 `1. 允许通知权限` → `2. 开启开发者选项` → `3. 开启无线调试并输入 6 位配对码`（采用「静默等待通道 + 检测到 `_adb-tls-pairing._tcp.` 端口瞬间全新高优 `CATEGORY_MESSAGE` / `SEMANTIC_ACTION_REPLY` 顶部横幅」双通道设计直接露出 `RemoteInput` 输入按钮，并明确提示折叠时单指下滑/长按展开及小窗/分屏手动填码兜底）→ `4. 测试本机连通性并一键启用`，底部折叠展示通知展开、重启恢复、双区焦点隔离与常见机型贴士；主界面在无感模式未配对或重启后无线调试关闭时弹出直达引导或一键切回标准模式的快捷对话框。
   - **投送时手机静音开关**（及实时状态说明；Android 13+ 无感单 App 模式下标注「单 App 无感环回静音，不影响其他 App 手机出声」，并在 `uid=2000` `AudioPolicy` 内自动启用双区音频焦点隔离，避免手机刷短视频暂停音箱音乐或恢复音乐导致视频短暂无声，停止/异常退出自动注销；iOS 受沙箱限制不支持 `AudioPolicy` 焦点接管）。
   - **自动识别正在播放的音源总开关**（Android，默认开启，仅从常用音源中已授权自动识别的 App 选取）、通知使用权实时状态与直达入口（Android）、电池优化豁免实时状态与直达入口（Android）。
3. **连接与调试（默认折叠）**：手动添加音箱 IP、音源模式分段选择（选定 App / 测试静音）、播放延迟（ms）输入框与同行右侧「生效」主按钮（支持 50–5000ms 及留空/0 自动；投送中点击直接调用 L1 `miplay_engine_set_playback_delay` / `NativeBridge.setPlaybackDelay` 清缓冲并热重锚广播 `TIME_OFFSET` 即时生效，无需断连重连，待机时保存并在下次连接生效；Android 与未来 iOS 共用同一交互与 L1 能力）、房间参考模式分段选择、认证模式分段选择、验收变体本地探针。
4. **关于与更新（Android & iOS 双端对齐）**：
   - 展示品牌名 + 当前版本号（自动剥离 `-release` 构建后缀，预览版/验收版附状态标注）+ 上次检查时间与右侧状态胶囊（`已是最新` / `有新版本` / `检测中…` / `检查失败`）。
   - 主操作按钮（`立即检查更新` / `查看新版本 vX.Y.Z`）、`启动时自动检查更新` 开关（默认开启、每 24h 向公开静态清单发起一次只读 HTTPS 请求、零遥测，关闭后 100% 零外网请求）、更新通道分段 `[稳定版 | 预览版 (RC)]` 与公开 Release 页面直达入口。
   - **Style B 更新详情弹窗（Android `Dialog` / iOS `.sheet`）**：消费 L1 Rust `miplay_update_evaluate_json` 返回的 `(current_version, target_version]` **跨版本区间更新日志**——相邻版本直出条目，跨多版本升级按新到旧分节展示各版本变更（正式版自动过滤已被汇总覆盖的中间 RC）；Android 支持应用内流式下载（`4dp` 胶囊进度条）+ 强制 SHA-256 与签名证书双重校验 + `FileProvider` 调起系统安装，并保留「前往浏览器下载」「稍后提醒」「跳过此版本」；iOS App Store 分发版走商店更新、自签/IPA 分发版跳转 Safari 打开 Release 页。

## 4. 图标规范（`design/icons/`）

- 统一画布 `24×24`，描边图标统一 `stroke-width="1.85"`、`stroke-linecap="round"`、`stroke-linejoin="round"`。
- Android 转为 `res/drawable/ic_ui_*.xml`（通过 `tint` 跟随 `UiPalette` 着色）；iOS 导入 Asset Catalog 并设为 `Template Image`。

## 5. 系统常驻通知文案规范（Android 前台服务 · 方案 2）

- **标题**：直指运行状态与音源名，避免暴露「无感/选定 App/配置延迟/E2E估」等工程术语：
  - 正常投送：`正在投送 · <音源名>`（全局媒体为 `正在投送 · 全局媒体`，静音测试为 `静音测试中`）
  - 连接中：`正在连接 · <音源名>`
  - 已暂停：`已暂停投送 · <音源名>`
- **收起态正文（严格单行定长，不随设备数增长）**：
  - **1 台设备**：直接显示真实设备名（如 `客厅音箱`；异常时追加 ` · 重连中` / ` · 已断开` / ` · 连接中`；无缓存名时回退完整 IP）。
  - **≥ 2 台设备**：统一简洁纯计数（正常：`N 台设备同步播放`；全部连接中：`正在连接 N 台设备`；已暂停：`N 台设备`；存在异常时聚合提醒：`N 台设备 · K 台重连中` / `M 台已断开`）。
- **下拉展开态（`BigTextStyle`）**：≥ 2 台设备时列出具体音箱明细（`• 设备名 · 状态`），异常设备置顶排序，最多展示前 5 台，超出末尾折叠为 `…等共 N 台设备`；操作按钮保留 `暂停/恢复` 与 `停止`。通知渠道名称统一为 `妙投 · 投送状态`。
- **iOS 边界说明**：iOS 无 Android 前台服务常驻通知，播控与连接状态由 App 内顶栏胶囊及系统「控制中心 / 正在播放」（或后续 Live Activities）承载，文案沿用同等去工程化口径。
